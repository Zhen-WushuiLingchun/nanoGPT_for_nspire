# Lesson 16 implementation plan: compact verified SFT v2

> Execute in batches. Lesson 16 ends after SFT v2 and frozen evaluation.
> Policy optimization and DeepSeek preference collection belong to Lesson 17.

## Frozen decisions

- Architecture: `GQA-ALiBi`, 6 layers, 6 query heads, 2 K/V heads, width 384,
  context 512, vocabulary 264.
- Parent: `GQA-ALiBi-Hybrid-SFT-Context512`, checkpoint SHA-256
  `f385a51f7ac4d53b1a640f9a977308a365bb032a6a2dbe53394ba035169513ee`.
- New route: `GQA-ALiBi-SFT-v2-Context512`.
- Primary output allowance: 256 tokens for both Direct and Think.
- Existing Lesson 12 frozen evaluation remains the primary ability gate.
- Lesson 16 uses no external API, teacher logits, RL, RLVR, RLAIF, DPO, GRPO,
  PPO, or preference model.
- Hard negatives are evaluation/future-preference records, not positive CE
  targets.

## Task 1: Implement exact compact reasoning records

**Output**

- `training/nanogpt_nspire/lesson16_data.py`
- `tests/python/test_lesson16_data.py`

**Contract**

- Parse GSM8K `<<expression=result>>` annotations with a bounded recursive
  parser that accepts only finite decimal/integer literals, unary signs,
  parentheses, and `+ - * /`.
- Never call Python `eval`.
- Verify every annotation result exactly.
- Accept only one to four annotations and require the last verified result to
  equal GSM8K's independently parsed final answer.
- Format project arithmetic and physics as one-to-four short English steps.
- Cap reasoning at 160 UTF-8 bytes.
- Reject special-token text, duplicate records, unverified values, division by
  zero, excess nesting, and overlong targets.

**Test**

```powershell
python -m pytest tests/python/test_lesson16_data.py -q
```

## Task 2: Build deterministic SFT v2 and challenge data

**Output**

- CLI in `lesson16_data.py`
- ignored artifacts under `artifacts/lesson16-data`

**Training inputs**

- 24,000 deterministic project arithmetic families, seed `20260729`;
- 12,000 deterministic project numeric-physics families, seed `20260729`;
- pinned GSM8K train rows whose one-to-four annotations pass exact checking;
- one Direct and one Think record per accepted family;
- context 512;
- family split seed `lesson16-sft-v2-split-v1`;
- every family in the Lesson 12 evaluation and Lesson 16 challenge evaluation
  is excluded before packing.

**Challenge slices**

- `in_range`;
- `range_shifted`;
- `sign_shifted`;
- `substitution_adversarial`.

Each JSONL row declares its slice and preserves the existing strict evaluation
fields. Challenge families are disjoint from training and every earlier frozen
evaluation family. Hard-negative metadata contains deliberately wrong
substitutions/finals for checker and Lesson 17 preference tests, but those
strings never enter positive training shards.

**Test**

- two independent builds are byte-identical;
- every shard/hash/count matches its manifest;
- no train/evaluation family overlap;
- operator, sign, magnitude, formula, task, and reasoning-step reports are
  present;
- hard-negative payload SHA-256 is recorded separately.

## Task 3: Add boundary-weighted SFT without changing inference

**Output**

- `training/nanogpt_nspire/sft_v2_train.py`
- minimal reusable loss hook in `efficient_train.py`
- route support in strict checkpoint/evaluation loaders
- `tests/python/test_sft_v2_train.py`

**Objective**

Ordinary assistant targets retain weight 1. `<FINAL>` and `<EOS>` targets that
are already eligible under the assistant mask receive weight 4:

```text
sum(token_ce * target_weight) / sum(target_weight)
```

Direct mode seeds `<FINAL>`, so its generated boundary reward applies only to
`<EOS>`. Think mode must generate both `<FINAL>` and `<EOS>`. This remains
weighted supervised cross-entropy, not reinforcement learning.

**Frozen compute**

- 1,000 optimizer updates;
- micro batch 2, gradient accumulation 4, context 512;
- 4,096 sampled tokens/update and 4,096,000 total sampled tokens;
- seed `20260729`;
- max/min LR `1e-4 / 1e-5`;
- warmup 50, evaluation every 100 updates;
- selection by ordinary unweighted validation CE, while recording weighted
  training loss separately.

**Test**

```powershell
python -m pytest tests/python/test_efficient_train.py \
  tests/python/test_sft_v2_train.py -q
```

## Task 4: Train and evaluate

**Output**

- `artifacts/lesson16-sft-v2/run.json`
- Direct and Think 256-token evaluation JSON on both primary and challenge
  sets.

**Primary gates**

- Direct format/mode compliance remains 100%;
- Think format/mode compliance and `<FINAL>` transition exceed the Lesson 15
  baseline of 75.78125%;
- Think budget truncation is below the Lesson 15 baseline of 20.3125%;
- primary exact accuracy does not fall below the parent checkpoint's 2/128
  Direct and 2/128 Think results.

The aspirational 95% Think completion target is reported honestly, not changed
after seeing results. Failure means this checkpoint is not promoted as the
Lesson 17 RL starting point.
